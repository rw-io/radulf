# Release a draining worker's own runs, deliveries, leases and registry row before it exits

A worker that gives up its graceful drain (or exits cleanly) now hands its work back before `process.exit(0)`: the new `Orchestrator.releaseOwnedWork()` stops its timers, interrupts every `running` run it owns with exit reason `worker shut down before this stage finished` (resumable loops go straight back to Ready, other stages park in Needs Attention), fails any review delivery it was running, frees its `repo_leases` rows and deletes its own `workers` row — so a replacement worker claims the card on its first pump instead of waiting `workerStaleSeconds` for the stale reaper. The reaper's per-run and per-delivery bodies were factored into shared `interruptRun`/`failDelivery` helpers so both paths write identical state; `shutdown.ts` calls the release on both the clean and the timeout branch and logs `interrupted N runs and M deliveries owned by this worker`. New `orchestrator.shutdown.test.ts` (6 DB-backed cases) and `shutdown.test.ts` (fake-timer clean/timeout paths) cover it; all acceptance criteria, `tsc`, `eslint` and `make check` pass. One caveat for the reviewer: the new orchestrator test shares `os.tmpdir()/runtmp` with `orchestrator.reaper.test.ts` and the two fail when run together as a two-file selection (the full suite is green).
